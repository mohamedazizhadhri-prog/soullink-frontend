1.3 Presentation of the SoulLink Project

1.3.1 Project Description

SoulLink is a full-stack web platform built to combat social isolation by
intelligently connecting people based on psychological compatibility rather
than superficial criteria. The platform proposes a unique pathway for each
user:

Step 1 â€” Secure Registration
The user creates an account with an email address or phone number and a
password. The system enforces an age check (18+ years old, verified in
auth.schema.ts via Zod validation). A 6-digit OTP code is sent by email
or SMS to verify the user's contact details (source: auth.service.ts,
functions: register(), verifyEmail()).

Step 2 â€” Biometric Identity Verification
During signup, the user must enroll their face using the browser camera.
The Face-api.js library generates a 128-dimensional descriptor vector, which
is stored in the user's PostgreSQL record (schema.prisma: User.faceDescriptor
Json?). This prevents identity duplication (threshold: Euclidean distance
< 0.45) and enables future facial login (loginWithFace(), threshold: 0.6).

Step 3 â€” Personality Discovery (Soul Games)
After verification, the user completes mandatory Soul Gamesâ€”a series of
interactive, episodic narrative games. Each scene presents a choice; the
user's responses calculate their Big Five (OCEAN) personality scores
(openness, conscientiousness, extraversion, agreeableness, neuroticism),
stored in the PersonalityProfile model (soulgames.service.ts: completeGame()).

Step 4 â€” AI Companion (Nova)
Each user is assigned Nova, a personal AI companion powered by the Groq
LLM API (model: llama-3.3-70b-versatile). Nova has persistent memory stored
in the NovaUserMemory PostgreSQL model and vector memory in Pinecone. Nova
adapts her mood and tone dynamically according to 20+ emotional states
(nova.prompt.ts) and proactively initiates conversations.

Step 5 â€” Intelligent Matching
Once a personality profile exists, the system proposes anonymous matches
with other compatible users. Initial conversations are anonymous, and identity
can be progressively revealed. Both 1-to-1 and group matches (3-8 users,
24h sessions) are supported (schema.prisma: Match, GroupMatch models).

Step 6 â€” Community and Communication
Users can join or create community servers with multiple channels, send
direct messages, share GIFs (Giphy), images (Cloudinary), and communicate
via a real-time Socket.IO layer. The platform exposes a rich chat interface
with emoji picker, file sharing, GIF search, pinned messages, and reply
threads (community.service.ts, chat.service.ts).

1.4.2 Critique of Existing Solutions

The analysis of existing platforms reveals five critical and recurring
limitations, as explicitly identified in the Cahier des Charges (Section 1.3):

  1. SUPERFICIAL CONNECTIONS
    Existing platforms match users based on photos, job titles, or basic
    listed hobbies. They have no mechanism to understand the user's actual
    psychological profile, values, or emotional world.

  2. ENGAGEMENT-OPTIMIZED ALGORITHMS
    Platforms like Facebook and Instagram are designed to maximize time spent
    on the platform, not to generate meaningful human bonds. This creates a
    perverse incentive that actively works against authentic connection.

  3. LACK OF REAL-WORLD TRANSITION
    Digital interactions almost never evolve into real friendships. There is
    no progression systemâ€”no mechanism that guides users from a digital chat
    toward a real-world meeting.

  4. INABILITY TO UNDERSTAND PERSONALITY
    No major platform currently uses advanced AI or structured psychological
    evaluation to truly understand who a user is. The closest attempt
    (OkCupid) uses static questionnaires, not interactive games.

  5. IDENTITY FRAUD (CATFISHING)
    The absence of identity verification on virtually all social platforms
    leads to widespread fraud and a fundamental erosion of trust. Users have
    no guarantee that the person they are speaking to is who they claim to be.

3.6 Soul Games Module

The Soul Games module is the personality discovery engine of SoulLink. It is
the third and final gate in the onboarding pipeline and the most strategically
important feature of Sprint 1.

Each Soul Game is an episodic narrative game composed of scenes. Each scene

OCEAN personality trait weights (openness, conscientiousness, extraversion,
agreeableness, neuroticism), and upon completing an episode, the system
calculates and stores the user's PersonalityProfile.

Critically, completing Episode 1 of the Soul Games is mandatory during
onboarding. Only after completing it does the system upgrade the user's
AccountStatus from PENDING_SOUL_GAME to ACTIVE, giving them full access to
all platform features including matching.

--- Extract 4: OCEAN Score Calculation â€” soulgames.service.ts ---------------

The Big Five personality scores are calculated by averaging the choice weights
for each domain (O, C, E, A, N) and normalizing to a 0.0â€“1.0 scale. If the
weight is 0, the choice is neutral for that trait and excluded from the average.

private calculateScores(responses: any[]) {
const domains: Record = {
O: [], C: [], E: [], A: [], N: []
};

for (const response of responses) {
  const choice = response.choice;
  if (choice.openness !== 0)          domains.O.push(choice.openness);
  if (choice.conscientiousness !== 0) domains.C.push(choice.conscientiousness);
  if (choice.extraversion !== 0)      domains.E.push(choice.extraversion);
  if (choice.agreeableness !== 0)     domains.A.push(choice.agreeableness);
  if (choice.neuroticism !== 0)       domains.N.push(choice.neuroticism);
}

const avg = (arr: number[]) =>
  arr.length > 0
    ? arr.reduce((a, b) => a + b, 0) / arr.length / 5
    : 0.5;   // default to 0.5 if no data for a domain

return {
  openness:          avg(domains.O),
  conscientiousness: avg(domains.C),
  extraversion:      avg(domains.E),
  agreeableness:     avg(domains.A),
  neuroticism:       avg(domains.N),
};

}
